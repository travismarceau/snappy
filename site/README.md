# getsnappy.fyi

The website, kept here rather than in a repo of its own.

It used to live in `travismarceau/getsnappy-site`, with a copy at
`store/site.html` in this repo. The copy went stale — it was missing the whole
download button, and still described a Mac App Store build that was abandoned
when the sandbox turned out to block the Accessibility API. Two copies of one
page is the kind of thing that only diverges. Now there is one.

## What is here

| File | Purpose |
|------|---------|
| `index.html` | The entire site. No build step, no dependencies, no framework. |
| `appcast.xml` | Sparkle's update feed. Generated by `scripts/build-direct.sh` — never edit it by hand, it carries EdDSA signatures. |

## Deploying

DigitalOcean App Platform serves this as a static site, behind Cloudflare.
`x-do-static-catchall-document` is `index.html`. The app is configured in the
DigitalOcean dashboard, not from a spec file in the repo.

To move the deployment here from `getsnappy-site`:

1. DigitalOcean ▸ Apps ▸ the getsnappy app ▸ Settings ▸ App-Level ▸ Source.
2. Repoint it at `travismarceau/snappy`, branch `main`, **source directory `site/`**.
3. Grant DigitalOcean access to the repo if it is still private.
4. Redeploy, then confirm `https://getsnappy.fyi/` and
   `https://getsnappy.fyi/appcast.xml` both answer 200.

Until that is done, the live site is still being served from `getsnappy-site`
and this directory is not yet authoritative. Archive that repo once the switch
is verified, so there is no second copy to drift into.

## Releases

The notarized zip is **not** committed. `site/*.zip` is gitignored: it is about
4 MB a release and git keeps every one of them for ever. It is published as a
GitHub Release asset instead, which is also what Rectangle does.

`scripts/build-direct.sh` derives the tag from `MARKETING_VERSION`, points the
appcast at
`https://github.com/travismarceau/snappy/releases/download/<tag>/Snappy.zip`,
writes the signed feed to `site/appcast.xml`, and prints the `gh release`
command to run. Commit `appcast.xml` and push so getsnappy.fyi serves it.

The download button on the page uses
`/releases/latest/download/Snappy.zip`, which GitHub resolves to the newest
release — so the page itself never needs editing at release time.

**This requires the repository to be public.** Release assets on a private
repository are not publicly downloadable, and both the download button and every
Sparkle update would fail for anyone who is not signed in with access.
